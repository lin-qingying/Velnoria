# 垂直切片 01：连接 → 区块 → 看见地形

第一刀切片。目标是在**不写世界生成、不写 sim**的前提下，打通"协议 → 世界数据 → UE 渲染"整条链路，验证 5 个最高风险假设。

## 1. 为什么是这一刀

总纲的模块清单可以任意顺序开工，但只有一条路径能最早证伪架构：

| 假设 | 若为假，代价 |
|---|---|
| A1 包表能由 `prepare` 导出并驱动编解码，而非手写 | 协议层要重写，P0 覆盖不可达 |
| A2 区块调色板 + 双通道光照可正确解码 | `world`/`light`/`render` 全部返工 |
| A3 贪心网格化 + UE 提交流水线能撑住视距 8~12 | 渲染架构换方案 |
| A4 核心层 / UE 的只读快照边界可行且无锁争用 | 线程模型重构 |
| A5 差分测试基础设施能在无原版素材的仓库里跑起来 | 全书验收手段失效 |

这 5 条不由模块数量决定，只由"跑通一次"决定。所以切片必须端到端，宁可每层都很薄。

## 2. 范围

**在范围内**

- `protocol`：Handshake / Status / Login / Configuration / Play 的**最小包集**（见 §4）
- `auth`：离线模式（UUIDv3）+ 连接在线服务器的令牌注入接口（实现可空，接口必须存在）
- `registry`：方块状态、方块 ID、群系 ID、维度类型，仅切片所需字段
- `world`：区块包解码、调色板容器、方块状态查表、双光照数组；**只读，不写存档**
- `light`：仅消费服务端下发值，不计算传播
- `render`：UE 插件骨架、区块网格化、单一批量材质、天空光近似、方块光体积纹理占位
- `player`：位置/朝向同步、相机跟随、无预测移动（服务端回显）
- `tools`：抓包录制器、区块快照导出器、逐方块比对器
- CI：P0 编解码往返 + P1 区块比对的可运行流水线

**明确不在范围内**（写出是为了拒绝范围蔓延）

- 世界生成、生物群系映射、结构
- 光照传播算法（只解码，不传播）
- sim 的任何 tick、实体、AI、红石、流体、合成
- 存档读写、单机模式、LAN、内置服务端
- 输入预测与校正、挖掘、放置、容器
- 音频、粒子、天气、实体渲染
- 材质美术、PBR 参数制作（切片用纯色 + 法线占位）
- 设置界面、语言切换、资源包

## 3. 交付物与验收

每阶段有独立门禁，未过不进下一阶段。

### S0 — 数据前置

输入来自本机正版安装，路径与哈希见 `docs/environment.md`（当前为 `D:\GAMES\.minecraft\versions\26.3-Fabric`，客户端 jar sha1 已校验通过）。

`prepare` 能从用户本机 jar 导出：
- 包表（各状态、方向、包 ID、字段模式）
- 方块状态全量列表 + 全局 ID 映射
- 群系、维度类型最小集
- 版本哈希

**验收**：导出物哈希写入缓存清单；重复执行产出字节相同；不含任何原版文件内容（仅 ID 与结构）。

**已知阻塞**：本机缺官方服务端 jar，数据生成器无法运行。三条候选处置见 `docs/environment.md` §4，未定稿前 S0 视为阻塞。`lumenvox_prepare inspect` 当前返回退出码 3。

### S1 — Status 握手

TCP 连接 → Handshake(next=1) → Status Request → 解析 JSON 响应 → Ping/Pong。

**验收**：能打印服务器版本名、协议号、在线人数、MOTD 文本组件（含颜色段）。
级别：包编解码 P0，状态迁移 P1。

### S2 — 登录到 Play

Handshake(next=2) → Login Start →（在线模式：加密请求 + 会话哈希 + Login Success）→ Login Acknowledged → Configuration（客户端信息、已知包、注册表下发）→ Finish Configuration → Play。

**验收**：离线模式进入 Play 状态，收到 `Login (Play)`、`Synchronize Player Position`、`Set Center Chunk`、`Chunk Data and Update Light`。
在线模式：能从系统凭据管理器取出令牌完成 `Login Start` 与 `Encryption Response`，会话哈希输入串与原版逐字符一致（P0）。

**关键**：Configuration 阶段下发的注册表 NBT 必须完整保留并解析为 `registry`；解析失败时按 P0 处理（失败而非降级）。

### S3 — 区块解码（无渲染）

消费区块包与光照包，构建内存世界，输出：
- 区块内方块状态直方图
- 每格 sky/block light
- 区块 NBT 未知字段的保留率

**验收**：
- 与我方录制器导出的原版区块快照逐方块、逐调色板条目比对，P1 全等（该切片只要求被下发区块，不要求生成）
- 同一会话重复解码结果稳定
- 未知字段往返不丢（P0）

**这是切片的第一个硬门禁**：此处不过，说明调色板或光照布局理解错误，后面的渲染都是错的。

### S4 — UE 渲染

UE 插件加载核心层库 → 注册快照读取接口 → 生成线程池做贪心网格化 → 主线程批量提交 → 可见地形。

**验收**：
- 视距 8 区块、1440p、中端 GPU 稳定 60 fps
- 方块边界清晰无缝隙、无 Z-fighting
- 透明方块（水/玻璃）排序正确，无穿透
- 天空光方向与太阳位置一致；方块光体积纹理在洞穴内可读
- 断线或区块卸载时无残留网格、无崩溃
级别：P3 人工清单。

### S5 — 玩家与相机

位置包驱动相机，WASD 发送位置更新（无预测），服务端回显即移动。

**验收**：能走、能转视角、能上下线重连；位置抖动在无预测下可接受（记录抖动幅度，作为 M4 预测模块的基线）。

## 4. 最小包集

只列切片必需的，其余包解码为"未识别原始字节"并计数。

| 状态 | 包 |
|---|---|
| Handshake | Handshake |
| Status | Status Request / Response, Ping / Pong |
| Login | Login Start, Encryption Request / Response, Login Success / Disconnect, Login Acknowledged |
| Configuration | Client Information, Plugin Message(品牌), Known Packs, Registry Data, Update Tags(可空), Finish Configuration, Disconnect |
| Play | Login, Set Center Chunk, Chunk Data and Update Light, Block Update, Set Default Spawn Position, Synchronize Player Position, Set Player Position, Game Event, Keep Alive, Disconnect, System Chat |

包 ID 一律来自 `prepare` 导出的包表，代码中不出现字面量。

## 5. 快照契约（A4 的落地）

核心层与 UE 之间只有三种数据：

1. **区块快照**：`ChunkPos` + 方块状态数组（`u16` 全局 ID）+ 双光照数组 + 版本号。不可变，引用计数交付。
2. **世界增量**：`(pos, stateId)` 的批量更新，按 tick 序号排序。
3. **玩家状态**：位置、朝向、维度、tick 序号。

规则：
- 核心层不持有任何 UE 类型；UE 不持有任何可变核心状态。
- 跨线程只传快照与无锁队列项，禁止共享可变结构。
- 快照带 `tick` 与 `generation`，UE 侧丢弃过期快照而非阻塞等待。
- 切片阶段允许"每帧轮询最新快照"，不引入回调；引入回调留待 M2 压测后再定。

数据流：

```
网络线程 ──包──▶ 解码 ──▶ 世界状态（模拟线程独占）
                              │
                              ├─▶ 区块快照（不可变）──▶ 无锁队列
                              └─▶ 增量更新（tick 有序）
                                        │
                            UE 游戏线程 ◀┘ 取快照 → 入网格任务队列
                                        │
                            网格线程池 ──▶ 网格结果 ──▶ UE 渲染线程
```

## 6. 线程与预算

| 项 | 切片目标 |
|---|---|
| 网络线程 | 收发 + 解压 + 解密，不解析游戏语义 |
| 模拟线程 | 切片中只做世界状态写入与快照发布，无 tick 循环 |
| 网格线程池 | 每线程 ≥ 30 区块/秒（16³ 全非空最坏情况基准另测） |
| UE 游戏线程 | 每帧提交 ≤ 0.5 ms，聚合网格 ≤ 200 个/帧 |
| 内存 | 视距 12 时区块数据 + 网格 ≤ 2 GB |
| 包解析 | 单区块包解析 ≤ 3 ms（p99） |

预算写在这里是为了让超预算成为明确失败，而不是"以后优化"。

## 8. 开工前必须定的事

以下三项不定，S4 无法开始：

1. **核心层语言**：C++（与 UE 同构，零 FFI 成本）vs Rust（内存安全，C ABI 边界成本）。切片推荐 C++——S4 之前的所有工作都在验证边界可行性，此时引入 FFI 会混淆问题归因。若定 Rust，S0~S3 可先用 C++ 原型，但边界契约需提前冻结。
2. **UE 版本**：锁定单个 5.x 次要版本（含热修号），写进启动器检测与 CI 镜像。不锁版本意味着 Lumen 与几何体接口随时变动。
3. **快照传输形式**：进程内直接调用（插件与核心同进程）vs 独立进程 + IPC。切片推荐同进程，理由同 1；若后续需要崩溃隔离再拆。

## 9. 夹具策略（与待决第 2 项关联）

切片需要的最小夹具：

| 夹具 | 内容 | 版权风险 |
|---|---|---|
| 包字节样本 | 各状态若干包的原样字节 | 低（协议数据，非表达性内容） |
| 区块快照 | 方块状态 ID 数组 + 光照数组 | 中（可由本机录制重新生成） |
| 注册表导出 | 结构 + 哈希 | 中（同上） |

策略：仓库只提交**生成脚本 + 哈希清单 + 小型手写样本**；大夹具本地生成。
CI 分两级：公开 CI 跑手写样本与属性测试；本地/私有 CI 跑完整差分。
这决定 S3 门禁能否在公开 CI 复现——若第 2 项决策为"不入库"，S3 门禁改为"提交者可复现"。

## 10. 退出判据

切片完成 = 同时满足：

- A1~A5 全部验证通过，或已明确证伪并记录替代方案
- S0~S5 门禁全过
- P0 用例 100% 通过；P1 区块比对 100% 匹配
- 性能预算达标或已登记偏差
- `docs/parity/diffs/` 中切片相关模块无 `open` 缺陷
- 一份切片复盘：架构假设哪些成立、哪些需改，作为 M2 的输入

切口完成后进入 M2（世界生成 + 光照传播），此时差分基础设施已可用，后续每个模块都能独立验收。
