# 区块解码（存档路径优先）

| 项目 | 内容 |
|---|---|
| 一致性级别 | P1（状态一致），调色板与方块状态映射为 P0 |
| 状态 | draft |
| 覆盖 | 区域文件定位、解压、区块 NBT、方块状态调色板、群系调色板、区块内方块统计 |
| 不覆盖 | 光照传播计算（只读存档里的光照值）、实体、方块实体、高度图语义 |

## 1. 为什么先做存档而不是网络包

网络区块包没有可离线验证的来源：没有抓包就没有夹具。存档不同：用官方服务端在本地生成一个世界，`.mca` 就是官方产物，可以反复读取、逐方块比对。

所以顺序是：**先存档（可验证）→ 再网络包（同一份 NBT 结构，外加高度图与光照位图）**。

## 2. 区域文件

`.mca` 头 8 KiB：

| 偏移 | 大小 | 内容 |
|---|---|---|
| 0 | 4096 | 1024 个位置项，每项 4 字节：3 字节扇区偏移 + 1 字节扇区数 |
| 4096 | 4096 | 1024 个时间戳（本实现忽略） |
| 8192 | — | 扇区数据，每块：4 字节长度 + 1 字节压缩类型 + 数据 |

- 位置项全零 = 该区块不存在。
- 压缩类型：1 = gzip，2 = zlib，3 = 未压缩。当前只处理 2 与 3；1 需 gzip 头解析（后续补）。
- 长度字段包含压缩类型字节，不含自身 4 字节。

## 3. 解压

自带 inflate，不引入第三方库（见 `AGENT.md` §8.1）：

- 支持 zlib 容器的 raw deflate 解压，校验 2 字节头与 Adler-32。
- 输出上限必须由调用方给出，防止解压炸弹。
- 只实现解压；压缩在需要写出存档时再做。

## 4. 区块 NBT 结构（存档）

```
{ "DataVersion": int,
  "sections": [ { "Y": byte, "block_states": { "palette": [ {...} ], "data": [long] },
                  "biomes": { "palette": [string], "data": [long] } } ],
  "block_entities": [...], "Heightmaps": {...}, "isLightOn": byte, ... }
```

- 1.18 之后区块在 `sections` 里按 `Y` 分段；每段 4096 个方块。
- `palette[0]` 对应索引 0；`data` 是紧凑位打包的长数组，每个条目 `bits = max(4, ceil(log2(palette.size())))`，**条目不跨 long 边界**，所以每个 long 存 `64 / bits` 个条目。
- `palette` 缺失或长度为 1 时，`data` 也缺失，整段为 `palette[0]`（通常是空气）。
- `block_states.palette` 的每个元素是方块状态描述（含 `Name` 与可选 `Properties`），需要映射到全局状态 ID（来自 `block_states.tsv`）。

## 5. 索引顺序

段内索引：`index = (y * 16 + z) * 16 + x`，即 Y 最外层、Z 中间、X 最内。解码结果按此顺序存储，与渲染网格化的读取顺序一致。

## 6. 验收

| 用例 | 判定 |
|---|---|
| 解压往返 | 用参考实现生成的 deflate 流解压后与原字节相同 |
| 解压上限 | 超过上限返回 `frame_too_large`，不分配 |
| 区域定位 | 已知坐标的区块读出，扇区偏移与长度自洽 |
| 调色板索引 | 全空气段、单色段、多色段分别解码正确 |
| 与注册表一致 | 解出的每个全局状态 ID `<= block_states.tsv` 最大 ID |
| 世界统计 | 出生点区块的空气/实心比例与方块直方图落入合理区间，且两次读取相同 |

## 7. 未验证项

- 26.3 的存档结构是否与 1.21 一致：**未验证**。本地服务端生成的 `.mca` 是唯一依据；若字段名或位打包规则不同，解码会在第一次读取时失败或统计异常，届时以实测结果修正本文件与实现。
- 光照字段的位图布局未纳入本阶段，只透传不解释。
