## VarInt / VarLong

- 小端 7 位分组，每字节最高位为续位。
- VarInt 最多 5 字节（32 位），VarLong 最多 10 字节（64 位）。
- 严格解码，不做宽容归一化：
  - 超过最大字节数仍带续位 → `varint_too_long`
  - 末字节携带超出目标位宽的载荷位 → `varint_overflow`
  - 输入不足 → `truncated`
- 判定顺序必须是"先续位、后位宽"：否则 `FF FF FF FF FF 01` 会被误报为 overflow。

依据：公开协议规范对 VarInt 的定义；判定顺序无外部依据，属实现选择，由单元测试固定。

## 字符串

协议中存在两种字符串编码，**不可混用**：

| 用途 | 编码 | 长度前缀 |
|---|---|---|
| 协议字段（包内 string） | 标准 UTF-8 | VarInt 字节数 |
| NBT 字符串、聊天组件 | Java 修改版 UTF-8 | u16 码元数 |

修改版 UTF-8 的差异：

1. `U+0000` 编码为 `C0 80`，不写 `00`；
2. `U+FFFF` 以上字符编码为两个三字节代理对，**不出现四字节形式**；
3. 长度前缀计的是 UTF-16 码元数，不是字节数。

解码约束：

- 拒绝四字节形式与孤立续字节；
- 拒绝非 NUL 的超长编码（`C1 81` 不等于 `A`）；
- 孤立代理项无法表示为 UTF-8，降级为 `U+FFFD`（原版不会产生，仅作容错）；
- 码元数超过上限（默认 32767）直接拒绝。

依据：Java `DataOutput.writeUTF` 的公开规范；NBT 线格式的公开文档。

## UUID

- 线格式：两个 i64，高位在前，各为大端。
- 文本形式：8-4-4-4-12 十六进制，解析时接受无连字符的 32 位形式。
- 版本位：高半部位 12..15；变体位：低半部 62..63。
- **离线模式身份**：`md5("OfflinePlayer:" + name)` 的 16 字节，强制版本 3 与 RFC 4122 变体，再按大端拆为两个 i64。

验证数据（独立由参考实现计算，见测试）：

| 输入 | 期望 |
|---|---|
| `md5("")` | `d41d8cd98f00b204e9800998ecf8427e` |
| `md5("abc")` | `900150983cd24fb0d6963f7d28e17f72` |
| `offline_player("Notch")` | `b50ad385-829d-3141-a216-7e7d7539ba7f` |
| `offline_player("jeb_")` | `a762f560-4fce-3236-812a-b80efff0b62b` |

离线 UUID 只依赖名字，不依赖会话；同一名字在任何服务器上结果相同。

## 协议 String

- 长度前缀为 VarInt 的**字节数**，不是码元数。
- 载荷为标准 UTF-8，必须是合法编码，拒绝孤立续字节、超长编码、四字节以外的非法起始字节。
- 上限：32767 个 UTF-16 码元；校验时机为解码后，同时限制字节数不超过 `4 × 上限`，避免先用超长字节流换内存。
- 与 NBT 字符串的区别：长度单位、编码、上限判定全部不同，共用一个函数即 bug。

## Position

- 单个 i64，位布局：`x[38..63]`（26 位有符号）、`z[12..37]`（26 位有符号）、`y[0..11]`（12 位有符号）。
- 编码前必须对超出范围的分量做**符号扩展截断**（取低 26/12 位），而不是饱和到边界；原版行为是截断。
- 范围：x/z 约 ±3.35e7，y 为 ±2048。
- 解码时先做符号扩展，还原为三个 i32。

依据：公开协议规范的位置编码定义。截断与饱和的差异由用例固定，若后续差分测试出现分歧，以服务端行为为准并登记 `known-diff`。
